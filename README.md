# EventMind AI Agent

**EventMind** — это автономная экосистема для автоматического поиска, обработки и импорта данных о мероприятиях в ERP-систему Odoo 18. Проект объединяет интеллектуального ИИ-агента на базе LangChain/LangGraph, веб-сервер FastAPI для обработки запросов в реальном времени и защищенную связку Odoo + PostgreSQL, развернутую в изолированном Docker-окружении под управлением Nginx с поддержкой HTTPS (Certbot/Let's Encrypt).

---

## 🏗 Архитектура системы

Проект построен на базе микросервисной архитектуры и состоит из четырех изолированных контейнеров, объединенных в общую Docker-сеть:

1. **Nginx (Reverse Proxy):** Точка входа для всего внешнего веб-трафика (порты `80` и `443`). Обеспечивает SSL/TLS шифрование, автоматический редирект с HTTP на HTTPS, а также проксирование веб-сокетов (`/websocket`) для Odoo 18.
2. **FastAPI AI Agent (`agent`):** Бекэнд интеллектуального агента. Работает в зацикленном асинхронном режиме (Uvicorn), принимает запросы через REST API, сохраняет контекст диалога для каждого пользователя (`thread_id`) и взаимодействует с Odoo через официальное API.
3. **Odoo 18 (`odoo`):** ERP-система, содержащая бизнес-логику и интерфейс для работы с мероприятиями. Порты закрыты от внешней сети, доступ предоставляется только через Nginx.
4. **PostgreSQL 16 (`db`):** СУБД для долговременного и безопасного хранения данных Odoo. Данные изолированы в Docker-томах (`volumes`) для предотвращения потери информации при перезапуске контейнеров.

## 🚀 Быстрый запуск и развертывание

### 1. Требования к серверу

* Установленный **Docker** и **Docker Compose v2**
* Зарегистрированный домен, направленный на IP-адрес вашего сервера (`A-запись`)
* Выписанные SSL-сертификаты Let's Encrypt (Certbot), находящиеся по пути `/etc/letsencrypt` на хост-машине.

### 2. Настройка переменных окружения (`.env`)

Создайте файл `.env` в корневом каталоге проекта `/opt/eventmind/` и заполните его вашими данными. **Важно:** избегайте пробелов вокруг знака `=`.

```env
# === НАСТРОЙКИ БАЗЫ ДАННЫХ (PostgreSQL) ===
POSTGRES_USER=odoo
POSTGRES_PASSWORD=your_secure_password
POSTGRES_DB=odoo_db
POSTGRES_HOST=db
POSTGRES_PORT=5432

# === НАСТРОЙКИ ODOO ===
ODOO_MASTER=your_odoo_master_password

# === НАСТРОЙКИ ДЛЯ ИИ-АГЕНТА ===
ODOO_HOST=http://team3-odoo:8069
DB_NAME=odoo_db
ODOO_USER=odoo@ya.ru
ODOO_PASS=your_secure_password
OPENAI_API_KEY=sk-... # или ключ другого LLM-провайдера

```

### 3. Запуск инфраструктуры

Для развертывания всех сервисов одной командой (включая автоматическую сборку контейнера агента) выполните:

```bash
docker compose up -d --build

```

Проверить статус запуска и посмотреть логи можно с помощью команды:

```bash
docker compose logs -f

```

## 📡 API Интеграция агента (Эндпоинты)

После успешного запуска ИИ-агент начинает непрерывно слушать порт `8000`. Его интерактивная документация Swagger доступна по адресу: `http://your_server_ip:8000/docs`.

### Отправка сообщения агенту

* **URL:** `/chat/`
* **Метод:** `POST`
* **Заголовки:** `Content-Type: application/json`

**Пример тела запроса (Request Body):**

```json
{
  "message": "Добавь мероприятие 'Конференция по ИИ' на 12 июня 2026 года в 14:00",
  "user_id": 482910
}

```

**Пример успешного ответа (Response):**

```json
{
  "reply": "Мероприятие 'Конференция по ИИ' успешно запланировано и добавлено в календарь Odoo на 12.06.2026 в 14:00."
}

```

> 💡 **Контекстная память:** Благодаря параметру `user_id`, который внутри роутера конвертируется в `thread_id` для LangGraph, вы можете продолжить диалог без потери контекста. Например, следующим запросом отправить: *"Сдвинь это мероприятие на час позже"*, и агент поймет, о каком событии идет речь.

## 🛠 Обслуживание и DevOps-команды

* **Полная очистка и сброс баз данных (в случае рассинхронизации структур):**
```bash
docker compose down -v
docker compose up -d --build

```


*(Флаг `-v` полностью удаляет тома данных, позволяя Postgres и Odoo выполнить чистую инициализацию БД).*
* **Обновление зависимостей агента после изменения `requirements.txt`:**
```bash
docker compose up -d --build agent

```


* **Проверка доступности сервиса (Health Check):**
```bash
curl http://localhost:8000/health

```
